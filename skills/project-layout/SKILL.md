# Project Layout — the one directory distribution

> **Proposing a new directory, file convention, or declaration format?** That is
> public API in this ecosystem: skill **api-design** is the gate that must pass
> first — it applies to "a new file/directory convention, a new declaration
> format" as much as to an exported symbol.

Every application built on the webtyp framework (`veltylabs/*`,
`mjosefa-cms`, `iam`, `misitio`, …) uses **this** directory distribution — not
another. The only things that vary between projects are two **additive**
directories:

- **`edge/main.go`** — added for a cloud project deployed as a Cloudflare
  Worker via `webtyp/goflare`.
- **`cmd/migrate/main.go`** — added when the schema is reconciled from CI/CD
  or run manually (never inside the Worker's `main()` — that costs seconds of
  cold start).

Everything else below is fixed.

```text
/
├── config/                  // NÚCLEO: the single composition root (merges app/ + client/ + routes)
│   ├── config.go            // neutral: AppName, DefaultModuleID, Modules() — shared symbols
│   ├── server.go            // (!wasm)  ServerConfig/ServerDeps + server-side composition
│   ├── routes.go            // (!wasm)  Register(r router.Router) — THE server route mount point
│   ├── client.go            // neutral: ClientConfig, ClientDeps, BuildClient() → *platformd.Platform
│   ├── css.go               // (!wasm)  RootCSS() global theme — MUST be an importable package (ssr imports it)
│   ├── favicon.go           // neutral: FaviconSvg() string — app favicon declaration (auto-generated by webtyp if absent)
│   ├── lang.go              // neutral: init() registers the app's lang.RegisterWords dictionary + lang.OutLang(...)
│   └── layouts/             // leaf package for design presets (avoids import cycles)
│       └── crud.go          // neutral: the app's standard preset over crudview
├── modules/
│   ├── server.go            // (!wasm)  Server(db, ids, pub, tenantID) ([]router.OperationModule, error) — typed registry
│   ├── browser.go           // neutral  Browser(caller, ids, tenantID) ([]platformd.UIModule, error) — typed registry
│   └── <module_name>/       // ONLY for an app-local capability. A reusable domain module
│       │                    // (github.com/veltylabs/<m>) brings its own <m>/ui — the
│       │                    // registries import it and NO modules/<m>/ dir exists (§4b)
│       ├── module.go        // neutral: ID, Label — the module's identity, nothing else
│       ├── server.go        // (!wasm)  Server(...) (router.OperationModule, error) — the domain library's *Module
│       ├── browser.go       // neutral  Browser(...) (platformd.UIModule, error) — built via <domainlib>.NewView(caller)
│       ├── model.go         // neutral: model.Definition literals (only if this module owns tables)
│       ├── model_orm.go     // GENERATED by ormc — never hand-edit
│       └── svg.go           // (!wasm) Icon = sprite.Define(...) — per-module CSS/icons
├── tests/                   // EVERY test in the repo lives here — package tests, imports config
│   ├── setup_test.go            // TestMain, buildUnderTest(), generic fakes
│   ├── <m>_contract_test.go     // real caller ↔ httptest
│   ├── <m>_view_mock_test.go    // mock caller for the view
│   ├── <m>_view_test.go         // view: neutral (no tag)
│   └── <m>_view_wasm_test.go    // view: //go:build wasm — real DOM, activates the browser suite
├── web/                     // ONLY thin main() — no logic, no theme, no wiring
│   ├── client.go            // (wasm)  main(): origin → config.BuildClient
│   ├── server.go            // (!wasm, GENERATED by WebTyp) // Code generated by https://webtyp.com. DO NOT EDIT.
│   │                        //   Compiles to web/server binary for deployment
│   └── public/              // static assets (index.html, generated CSS, wasm, JS runtime)
│
├── edge/main.go             // (wasm, OPTIONAL) Cloudflare Worker entrypoint — goflare projects only
└── cmd/migrate/main.go      // (!wasm, OPTIONAL) schema reconciliation for CI/CD or manual runs
```

## The invariants

### 1. `config/` is the composition root — one package, not `app/` + `client/`

Server and client share real symbols (`AppName`, `DefaultModuleID`, the
module list, security-event names). Two packages can't share them without
inventing a third. `config/` defines them **once** in a neutral file; both
targets see it. Each file is a **configuration layer**:

- `config.go` — neutral (no build tag): shared constants + `Modules()`.
- `server.go` — `//go:build !wasm`: `ServerConfig`, `ServerDeps`, and the
  server-side composition (`db`, ids, publisher, the domain modules).
- `routes.go` — `//go:build !wasm`: `Register(r router.Router)` mounts the app
  routes onto the server.
- `client.go` — **neutral** (so the view rail runs in stdlib tests):
  `ClientConfig`, `ClientDeps`, `BuildClient() → *platformd.Platform`.
- `css.go` — `//go:build !wasm`: `RootCSS()` global theme.
- `favicon.go` — **neutral**: `FaviconSvg() string` app favicon declaration.
  Auto-generated by `webtyp` dev server on startup with the WebTyp SVG mark
  if missing. Documented inline with instructions on customizing the SVG or
  using an image asset.

**Naming rule — never `config.Config`.** `client.go` is neutral and
`server.go` is `!wasm`, so under `!wasm` compilation both compile at once. A
`config.Config` defined in both would collide. Types are explicit per layer:
`ServerConfig`/`ServerDeps`/`BuildServer` vs `ClientConfig`/`ClientDeps`/
`BuildClient`. Zero-value deps = production wiring; injected doubles = test.

### 2. Dependency direction: `config → modules`, NEVER `modules → config`

The core depends on the leaves, never the reverse. `config/` must not be
imported by anything under `modules/`. A module that needs a shared preset
imports `config/layouts/` (a leaf that imports neither `modules` nor
`config`). Verify: `grep -rn "<module-path>/config" modules/` → empty.

### 3. `web/` is thin `main()` only

`web/client.go` (and `web/server.go`) are `package main` —
**not importable from `tests/`**. They only resolve config from the
environment/origin and call into `config`. No logic, no theme, no wiring lives
here. (This is why `RootCSS()` is in `config/css.go`, not `web/`: the `ssr`
extractor *imports* the package exposing `RootCSS()`, and a `package main` is
not importable.)

### 3b. The server main is GENERATED into `web/server.go`

**Declaring `config/routes.go` is the whole requirement.** `webtyp.com/server`
decides the mode at startup (`server/main_decision.go`):

```go
usesGeneratedMain() = HasRoutes(rootDir) && !hasHandWrittenMain()
needsExternalProcess() = hasHandWrittenMain() || usesGeneratedMain()
```

and logs which branch it took, with the path that drove it:

| Log line | Condition |
|---|---|
| `External mode: config/routes.go present, generated main from …` | `config/routes.go` exists, generated main in `web/server.go` → **the normal case** |
| `External mode: user-written server main at …` | `web/server.go` exists without generated header → the escape hatch |
| `Internal mode: no config/routes.go and no server main, checked …` | neither → assets served from memory, **no backend at all** |

The generated main is written to **`web/server.go`** and is `// Code generated by https://webtyp.com. DO NOT EDIT.`. It
already builds the server for you:

When `config` defines `RunServer() error`, the generated `web/server.go` is minimal:

```go
func main() {
    if err := config.RunServer(); err != nil {
        log.Fatal(err)
    }
}
```

Otherwise, for simple route-only projects, it generates:

```go
s := httpd.New(httpd.Config{
    Port:      "8080",
    PublicDir: "web/public",
    Gzip:      true,
    Health:    true,
    TLS:       httpd.TLSConfig{PlainHTTP: false}, // Native HTTPS with devcert
})
config.Register(s.Router())
s.ListenAndServe()
```

So `httpd.New`, the port, the public dir, gzip, health and dev TLS are **not
yours to write**. A hand-written `web/server.go` is only an escape hatch.
The output binary is compiled to `web/server` (or `web/server.exe`).
To deploy: copy `web/server` + `web/public`. Both are already in `.gitignore`.

**`Register` must take exactly one parameter:**

```go
func Register(r router.Router)                       // → config.Register(s.Router())        ✅
```

With more than one parameter the generated call passes `nil` and the app boots
with no modules mounted. If `Register` needs composed dependencies, it calls
into `config/` itself — the composition root is `config/`.

### 4. A module is `server.go` + `browser.go` — typed, never a `[]any` bag

The axis of a module is not "front/back" — it is **where the code runs**, and
that axis already exists: the build tag imposes it. Naming the pair after that
axis is what makes the name and the tag say the same thing:

```go
// modules/<m>/server.go — //go:build !wasm
func Server(db *orm.DB, ids model.IDGenerator, pub events.Publisher, tenantID string) (router.OperationModule, error)

// modules/<m>/browser.go — neutral, NO build tag
func Browser(caller router.Caller, ids model.IDGenerator, tenantID string) (platformd.UIModule, error)
```

Both return the typed contracts the ecosystem already publishes —
`router.OperationModule` (`webtyp.com/router`) and `platformd.UIModule`
(`webtyp.com/layout/platformd`). **Never `[]any`.** A bag with no type forces a
neutral file to call into both targets, which is what used to force a
`*_wasm.go` stub whose entire body was `return nil` — that stub is gone because
nothing neutral calls `Server` anymore.

`modules/server.go` and `modules/browser.go` are the two typed registries — one
append per module, one per file, never merged into one `[]any` list:

```go
// modules/server.go — //go:build !wasm
func Server(db *orm.DB, ids model.IDGenerator, pub events.Publisher, tenantID string) ([]router.OperationModule, error)

// modules/browser.go — neutral
func Browser(caller router.Caller, ids model.IDGenerator, tenantID string) ([]platformd.UIModule, error)
```

A construction failure is now a returned `error` — the server does not boot
half-wired with a silently missing module.

**The build tags are NOT symmetric, and that is deliberate** — this is the
detail an agent with no context gets wrong if nobody writes it down:

| File | Tag | Why |
|---|---|---|
| `server.go` | `//go:build !wasm` | Never referencing the domain constructor under wasm is the only reason the linker can strip that code from the browser binary. |
| `browser.go` | **none** | `tests/<m>_view_test.go` is a stdlib rail with no browser. A `wasm` tag here silently drops that test file from every non-wasm build. |
| `module.go` | **none** | `ID` is needed by both server-side RBAC and the client-side nav. |
| `svg.go` | `//go:build !wasm` | `ssr` reads it at compile time; it never runs in the browser. |

- The **browser view** is built in `browser.go` via `<domainlib>.NewView(caller)`
  and wrapped in a `platformd.UIModule`. **All of a module's view construction
  goes in `browser.go`** — never scattered across other files. Domain-specific
  interactive wiring may live in area-named files, but the view itself is
  `browser.go`.
- **Lazy Module Activation (`Activate()`)**: `platformd.UIModule` requires `Activate()`.
  Modules must NEVER eager-fetch data inside `Init()`. Eager-fetching on `Init()`
  wastes network calls on startup for screens the user hasn't visited. `Activate()` is
  called by the platform chassis only when the module becomes active (on initial route or
  navigation). Views like `crudview.CrudView` memoize this load (`v.loaded`) so subsequent
  visits do not re-fetch unless explicitly reloaded.
- `server.go` (`!wasm`) returns the domain library's `*Module` wrapped as
  `router.OperationModule` — propagate its error, never swallow it into `nil`.
- Per-module CSS/icons live in that module's dir (`svg.go`, `css.go`), read by
  `ssr` only from files named exactly `css.go`/`js.go`/`svg.go`/`html.go`.
- **Flat: no subdirectories inside a module**, with one exception: `docs/` (a
  module's own documentation lives beside the code it documents). Any other
  subdirectory — `find modules -mindepth 2 -type d | grep -v /docs` → empty —
  is almost always code hiding: an `internal/`, a helper package, a local copy
  of something that belongs upstream.
- Canonical file names: `module.go`, `server.go`, `browser.go`, `model.go`,
  `model_orm.go` (generated), `svg.go`, `css.go`. **Forbidden inside a module
  dir:** `init.go`, `backend.go`, `view.go`, `frontend.go`, any `*_wasm.go` —
  each is either the untyped bag this section replaces, or names the layer
  instead of the target.

This structure is meant to be enforced, not just documented:
`webtyp.com/router/layoutscan.VerifyLayout` statically checks it (file names,
tag symmetry, no `[]any` return, no test outside `tests/`) — see the checklist
below to run it by hand today. Wiring it into the dev daemon so a violation is
a build error automatically is tracked separately and not yet shipped.

### 4b. A reusable module brings its own view — the app only lists it

When the capability is a reusable domain module (`github.com/veltylabs/<m>`), the
app writes **no** `modules/<m>/` directory. The module repo carries:

- `<m>/ui` — `ID`, `Label`, `Browser(caller, ids, tenantID) (platformd.UIModule, error)`
  plus its `css.go`/`svg.go`. The domain root package still never imports `layout`,
  so a server binary never links the UI.
- `<m>/seed` — `Load(...) (Data, error)`: demo data written through the module's own
  methods.
- `<m>/web/client.go` — the module's runnable demo (in-browser: `storage/mem` +
  `router/loopback` + seed, no login). Run `webtyp` at the module root to see and
  test the screen; **a screen is built and tested there, never in the app**.

The app then keeps only the two registries:

```go
// modules/browser.go — neutral: one line per screen, imports <m>/ui
views = append(views, itemcatalogui.Browser(caller, ids, tenantID))

// modules/server.go — //go:build !wasm: builds each domain *Module once and wires
// the cross-module ports (e.g. devicemanager.IPLocator into staff_manager, the four
// readers into appointment_booking). When modules wire each other, return a typed
// struct (Backends{...}) with an Operations() []router.OperationModule method, so
// the auth trust store and event subscriptions share the same instances.
```

Rules the module repos follow (their `AGENTS.md`): dependencies between modules form
a DAG (`ui/`, `seed/`, `web/` import only upstream modules); a screen that mixes
modules lives in the **most-downstream** module it touches (e.g. "Personal" =
staff + schedule lives in `appointment_booking/ui`). The app just lists it.

### 5. Every test in `tests/`

TODO test of the repo — unit, view, WASM view, contract, integration — lives
under the root `tests/` directory (`package tests`, imports `config`). Nothing
in `modules/` or `config/` carries a `_test.go` file. Run with `gotest` (never
`go test`): it runs native + browser in one command; the wasm suite activates
by `//go:build wasm`, not by name.

### 6. Neutral vs `!wasm` files

Neutral files (no build tag) import only cross-platform types — they compile
in stdlib tests *and* wasm. `!wasm` files (`svg.go`, `css.go`, `server.go`)
may import SSR types. A neutral file that imports an SSR-only package breaks
the view test rail. Inside a module, `server.go`/`browser.go` are the file
pair this applies to most often — see §4's tag table; getting it backwards
(`browser.go` tagged `wasm`) drops the stdlib view-test rail silently, with no
compile error to catch it.

### 7. `config/lang.go` is the app's one translation dictionary

A webtyp library never hardcodes a human language for its own chrome text
(dialog titles, confirmation messages, calendar month/weekday names, …) —
it renders the English canonical word through `lang.Translate(...)`
(`webtyp.com/fmt/lang`) and registers nothing itself. `config/lang.go`
is where the APP decides: an `init()` calling `lang.RegisterWords([]lang.DictEntry{...})`
for every word a library it uses actually renders, plus `lang.OutLang(...)`
to activate the target language. Neutral (no build tag) — translated text
can render on either the server or the client side. It has no effect unless
something imports `config` (an `init()` in an unimported package never
runs) — `web/client.go` (and `web/server.go`, if present) must import
`config`, even if only blank (`_`), same as any other composition-root
side-effect import. Adding a module that pulls in a new component with its
own translatable chrome adds words to this SAME file — never a second
dictionary file. Full rationale and the consumer-side contract:
`https://github.com/webtyp/layout/blob/main/docs/DICTIONARY.md`.

## Transport variants

The canonical transport is **MCP** (`mcp.HarvestOps` on the server,
`mcp.NewCaller(mcp.NewClient(origin, ""))` on the client). HTTP/REST stays for
binary uploads, static SSR, and auth flows.

A project may instead use **plain REST** for its own API (e.g. a Cloudflare
Worker where MCP-over-goflare is unproven). Then:

- `routes/routes.go` carries the **explicit mount table** — every
  `r.Get/r.Post/...` with its `.Public()`/`.Authenticated()`, and nothing else.
  It is the REST equivalent of `modules/server.go`'s op-registration. (The file
  itself is not REST-specific: **any** project with a backend declares it — see
  §3b. What REST changes is what goes *inside* it.)
- The renderer-touching half of the modules moves to a `modules/panel/`
  package (`//go:build wasm`) that `routes/` **never** imports — that missing
  import is the package boundary keeping `dom`/`layout`/`crudview` out of
  `edge.wasm` (a build tag is not enough: `goflare`/`sitec` pass no `-tags`).
- Server-side handler modules stay flat under `modules/<domain>/`
  (`handler.go`, `server.go`) — same forbidden-name list as §4: no `backend.go`.

Everything else — `config/` as leaf composition root, thin `web/` mains, all
tests in `tests/`, views in `browser.go`, no subdirs in a module — is unchanged.

## When adding the optional dirs

- **`edge/main.go`** (`//go:build wasm`): builds the D1/R2 bindings, calls
  `config.New...`/`routes.Register` (or the MCP mount), `edge.Serve(r)`. It
  never does schema DDL.
- **`cmd/migrate/main.go`** (`//go:build !wasm`): reads `CLOUDFLARE_*` /
  `D1_*` env, runs each package's `Migrate`/`Sync` against the D1 HTTP API.
  Invoked from the deploy workflow (`pre-deploy: go run ./cmd/migrate`) or by
  hand. Thin main: parsing + DI + print/exit only.

## Checklist for a structure review

- [ ] `config/` imports nothing from the repo's own module tree.
- [ ] `web/*.go` are `package main`, contain only env/origin resolution + a call into `config`.
- [ ] **A project with a backend declares `routes/routes.go`, and `Register` takes exactly one parameter (`router.Router`).** More parameters make the generated main pass `nil`.
- [ ] **No `web/server.go` unless the generated main genuinely cannot serve** — check the startup log says `External mode: routes/routes.go present, generated main from …`, not `user-written server main at …`.
- [ ] `.build/` is in `.gitignore` (the daemon adds it; verify it survived).
- [ ] `RootCSS()` is in `config/css.go` (`!wasm`), not `web/`.
- [ ] `config/lang.go` holds the app's only `lang.RegisterWords` call; no library registers its own dictionary; `web/client.go` (and `web/server.go`, if present) import `config`.
- [ ] No `modules/<m>/` duplicates a reusable domain module that ships `<m>/ui` —
      the registry imports `github.com/veltylabs/<m>/ui` instead (§4b).
- [ ] Every `modules/<m>/` has flat files only (`docs/` excepted); its view is
      in `browser.go`, never `view.go`/`backend.go`/`init.go`/`*_wasm.go`.
- [ ] No function under `modules/` returns `[]any` or `[]interface{}`.
- [ ] `server.go` carries `//go:build !wasm`; `browser.go` and `module.go` carry
      no build tag at all — verify with `webtyp.com/router/layoutscan.VerifyLayout`.
- [ ] No `_test.go` outside `tests/`.
- [ ] `config.Config` does not exist — types are `ServerConfig`/`ClientConfig`.
- [ ] `edge/main.go` does no schema DDL; `cmd/migrate/main.go` is a thin main.
- [ ] (REST projects) `routes/routes.go` is the only file with `r.Get/r.Post`; `routes/` never imports `modules/panel/`.
