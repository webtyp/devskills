# Module layout

Rules of what a module may import, tenancy and status codes: the module's `AGENTS.md`. This skill is **where each piece goes**.
Reference: `veltylabs/modules/pharmacy_manager` (domain with stock) and `service_catalog` (catalog with child tables).

## Root package — one file per role

| File | Holds | Never |
|---|---|---|
| `model.go` | `ModelName`, enum constants, every `model.Definition` (tables, then operation arguments, then results) | logic |
| `model_orm.go` | generated by `ormc`; never edited (run `gofmt -w` after it, restore `go.mod`, `go mod tidy`) | hand edits |
| `errors.go` | `domainError` constants (messages start `<module>: `), `ValidationError`, `decodeError`, `statusOf`, `writeError` | anything else |
| `module.go` | `Deps`, `Module`, `New`, event topics, the domain operations and the rules an entity's fields cannot express | handlers, wire shapes |
| `crud.go` | update / upsert / patch / deactivate / delete of the editable entities; `<entity>ByID` for operations that arrive without tenant | queries |
| `queries.go`, `reports.go` | lists and gets; reports (`ListExpiring`…) and **readers for other modules** | writes |
| `ops.go` | `Op*` names, `res*` RBAC resources, the wire shapes the generic view sends (`{records}`, `{ids, fields, record}`, `{ids}`), `MountOperations`, one handler per operation | domain rules |
| `view.go` | one `New<Entity>View(caller)` per screen (`Item()` is generated by `ormc` from `Item: model.ItemLabel…` marks on the fields of `model.Definition`; a screen has no `Lookups`) | renderer imports |
| `<concept>.go` | a self-contained concept with its methods and handlers (`recipe.go`) when it would bloat the files above | — |
**Every table of a module starts with the module's prefix** — its first word: `room_layout` → `room_floor`, `room_space`; `staff_manager` → `staff_member`. In the database and in any schema listing the module's tables sort together. The name is `<prefix>_<noun>`, never the bare prefix nor a bare noun (`equipment` → `room_equipment`); a table that links two of them joins both nouns (`room_space_equipment`). Argument and result Definitions (no table) keep their own names. Renaming a table later is an `ALTER TABLE … RENAME` in every database by hand: `ddl.Sync` creates what is missing, it never renames.
**Never trust the request for who or where:** the tenant comes from `Deps.TenantID` (server configuration) and the acting user from `ctx.UserID()`; args sent by the browser carry neither (`TenantId`, `ActorId`, `CreatorUserId`… are not fields of an args type). A value the client sends can be forged.

**A file is named for its role, never for a transport or a tool**: no `mcp.go`, `http.go`, `rpc.go`. The module speaks
`router.OperationModule`; which transport harvests it is the app's choice.

## Sub-packages

| Dir | Holds |
|---|---|
| `migrate/` | `Migrate(conn ddl.Execer, c ddl.Compiler) error`: every table in foreign-key order, with a test of that order |
| `ui/` | no destination tag on render files; asset producers (`css.go`, `svg.go`, `image.go`…) `!wasm`; `ID`, `Label`, icons, `Screens(caller) []view.Screen`; a select filled from another list is a `view.Lookup` of the screen; never imports `layout` |
| `seed/` | `Load(m, tenantID) (Data, error)` through the module's own methods |
| `web/browser/main.go` | the runnable demo (no destination tag): `storage/mem`, `router/loopback`, `events/mock`, `unixid` |
| `tests/` | external package; `setup_test.go` holds the helpers (`newModule`, `new<Entity>`, `testTenant`, a test `IDGenerator`); one file per area; conformance suites in their own file; a constant used by untagged tests never lives in a `!wasm` file |

Root files beside the code: `lang.json` (positional, no `default`), `AGENTS.md`, `README.md` (quick start, operations table generated from `MountOperations`, readers, key files), `docs/ARCHITECTURE.md`, `docs/diagrams/database.md` (Mermaid ERD).

## Between modules

- **A module never imports another module — in any package**: root, `migrate/`, `ui/`, `seed/`, `web/`, `tests/`. It must move, build and test alone; it depends only on `webtyp` contracts, never on another module, a concrete database or a concrete transport. A module that needs another **declares a narrow interface** with the methods it uses; the app passes the instance. Its demo and tests use a fake of that interface. A screen that mixes modules lives in the app.
- **Too much coupling is a design defect, not a wiring problem**: if a module cannot live without another, either the other is merged into it (the module grows) or the boundary is redesigned until what is left is a narrow interface. A plan never adds an import of another module.
- So a reader meant for other modules has **plain-typed** arguments and results (`string`, `int64`, `float64`, `bool`, slices of them): `ServiceRecipe(tenantId, serviceId) (itemIds []string, quantities []float64, err error)`, `UseInRoom(tenantId, roomId, itemId string, quantity float64, docType, docId, by string) (int64, error)`, `RoomOfOccupant(tenantID, occupantID string, at time.Unix) (string, bool, error)`. A result typed with the module's own struct cannot be named by the consumer.
- A reference to another module's row is a soft id (`item_id`, `room_id`), never a foreign key.

## Time

The unit of an instant is its **type** (`webtyp.com/time`): `time.Unix` (seconds) for **dates and deadlines** (expiry,
booking day, session end), `time.Nano` (nanoseconds) for **the instant of an event** (`created_at`, `updated_at`).
Clocks: `time.NowUnix()`, `time.NowNano()`; durations: `time.Day`, `time.Hour`, `time.Minute` (typed `Unix`). Model
fields: `model.UnixTime()` / `model.NanoTime()`, never `model.Int()` for an instant. The units meet only through
`n.Unix()` / `u.Nano()`; never divide or multiply by 1e9. Formatters take `Unix`: `time.FormatDate(n.Unix())`.

## Adding an entity or an operation

1. Definition in `model.go` → `ormc` → format, restore `go.mod`, tidy.
2. Errors in `errors.go` and in `statusOf` (404 / 409 / 400).
3. Method in `module.go`/`crud.go`; handler and `MountOperations` line (resource + every action it performs) in `ops.go`.
4. Table in `migrate/` and its order test; `view.go` and `ui/` only if it has a screen (following **ui-consistency**).
5. Tests in `tests/`, docs (README operations table, ARCHITECTURE, ERD), `gotest` and `GOOS=js GOARCH=wasm go vet ./...`.
